# Stage 9 - Release Gate Checklist

Status: Complete; implementation tracking in progress.

Date: 2026-05-27

Last updated: 2026-06-11

Scope: release readiness gates for PIVX in Cake Wallet, derived from Stages 2-8. This checklist covers APK/TestFlight readiness, required node/Sapling RPC setup, mainnet/testnet policy, restore, transparent/shielded receive and send routes, sync/error handling, backup/security, QR/URI behavior, and release tester guidance.

Implementation note, 2026-05-27: wallet-side blocker fixes have started. Do not mark any external APK/TestFlight readiness gate complete until the relevant automated checks, canonical PIVX Core/ElectrumX verification, and manual tests in `10_test_plan.md` pass. Server-side ElectrumX/indexer follow-ups are tracked separately in `14_electrumx_followups.md`.

Wallet-side progress update, 2026-05-27:

- Sapling scan state now persists `nextTreePosition`, accepts explicit global output positions from `get_block_range`, and blocks birthday/post-activation sync when neither persisted tree cursor nor server-advertised global positions are available.
- Sapling `get_block_range` failures, null responses, malformed responses, and incomplete v1 envelopes now throw after retries instead of being treated as empty scanned ranges.
- PIVX Sapling sidecar state now requires Cake wallet encryption outside test-only storage, uses `.json.enc`, and migrates legacy plaintext only when encryption utilities/password are available.
- PIVX seed restore and several Sapling logs/errors are redacted; remaining crash/support/copy-path redaction still needs verification.
- PIVX route creation now blocks mixed outputs, shielded-source to transparent, and direct transparent-to-external-shielded sends before transaction construction. `t-to-z`/`z-to-t` builders are still unimplemented.
- PIVX create/open/restore now pass persisted mainnet/testnet policy into the wallet and Sapling stack. Sapling RPC capability probing was added for sync/send policy, including v1 capability and block-range envelope support.

Wallet-side hardening update, 2026-05-28:

- Legacy Sapling sidecars that lack a persisted `nextTreePosition` no longer get to trust an inferred max-owned-note cursor. Resumed post-activation sync now requires either a truly persisted cursor or server-advertised explicit global output positions.
- Sapling sync height and `nextTreePosition` now complete through one storage write only when the tree cursor is trusted. Empty ranges after an untrusted legacy cursor do not silently promote that cursor to trusted state.
- Explicit server global output positions are checked for partial data, contiguity, and mismatch with an existing persisted cursor.
- The v1 `get_block_range` envelope now rejects mismatched `from_height`/`to_height` metadata.
- Shared Electrum request logging no longer prints raw Sapling request params or response snippets, removing nullifier/witness/commitment metadata from that debug path.
- Added focused regression coverage for untrusted legacy tree cursors, atomic sync cursor persistence, encrypted migration preserving cursor trust state, failed-range non-completion, and v1 range envelope validation. `dart analyze` passes on touched files; `flutter test` remains blocked before execution by the repo dependency solver conflict.
- PIVX automatic node switching now probes candidate nodes for Sapling block-range capability before selecting them, so reachable generic Electrum nodes are not treated as valid shielded-wallet failover targets.
- Z-to-z spend construction now fetches one best anchor, validates every witness against that exact anchor root/height/commitment/position, and signs with the same anchor.
- Successful shielded broadcasts now reserve selected nullifiers as pending spends in encrypted Sapling storage, excluding those notes from later spend selection while awaiting mined nullifier reconciliation.
- Startup shielded balance loading now writes zero sidecar balance into the wallet balance map, reducing stale shielded display after zero-balance storage.
- Added PIVX log-redaction regression coverage for interpolated sensitive Sapling/seed metadata in PIVX logging paths. The shared send OpenCryptoPay catch path now avoids printing raw PIVX exceptions, and shared Electrum error logging no longer prints raw server error text.
- Shielded note storage now separates pending received, confirmed, and spendable shielded balances by note height and chain height. PIVX displays pending received shielded value as `secondUnconfirmed`, confirmed spendable shielded value as `secondConfirmed`, and z-to-z selection uses the same confirmed spendable set.

These updates move several Critical/High findings to `Needs Verification` in `11_findings_register.md`, but no external APK/TestFlight gate is closed yet because Flutter tests are blocked by dependency resolution, server-side ElectrumX v1 work is incomplete, and manual tests have not passed.

## Final Verdict

PIVX is NOT READY for external APK distribution or iOS TestFlight.

The current branch may be used only for tightly controlled internal engineering testing, with no real user funds, no public release notes implying PIVX Sapling support, and explicit out-of-band tester instructions. External APKs and TestFlight builds are blocked because shielded receive/send state can be wrong or incomplete, seed and shielded metadata can leak through logs/plaintext storage, network/testnet policy is not wired end to end, and the UI exposes routes and actions that do not match the implementation.
